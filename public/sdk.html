Promvis SDK — Integration Guide

Promvis SDK is a white-label, native-core AI stock-analysis assistant that securities firms (CTCKs) embed into their own mobile apps. The chat UI renders natively (Kotlin/Compose on Android, Swift/SwiftUI on iOS) — no WebView — with first-class bridges for Flutter and React Native.

⚠️ DRAFT / PREVIEW. The public API below is the intended integration contract. The distributable artifacts (AAR, Swift Package, plugins) are not published yet, and three backend decisions are still open (multi-tenant routing, token issuance, API versioning — see Open items). Names and coordinates may change.

1. What you get

  • A drop-in chat surface: streaming answers with GFM markdown, tables, inline + block LaTeX, and charts, rendered natively.
  • One launch entry point per platform — pass a ticker, get the assistant.
  • White-label theming + vi/en localization.
  • Advisory-only by design: the SDK never places orders, payments, or OTP, and never bridges into your trading flows.

You bring: a base URL + a way to mint a short-lived auth token for the logged-in user (your backend ↔ the AI backend). Nothing secret is hardcoded in the app.

3. Get credentials

You need two values, provisioned per tenant by the SDK vendor:

Value Example Where it lives
baseUrl https://<tenant>.ai-gateway.example.com App config / build-time env — never committed
auth token short-lived JWT Minted at runtime by your backend, fed to the SDK via a tokenProvider

🧪 Demo / sandbox environment. A shared demo AI backend is available on request — contact analyst@promvis.io for the sandbox baseUrl and a test token to try the SDK before your per-tenant instance is provisioned.

🔒 Keep secrets out of source. Inject baseUrl from your build config and obtain the token at runtime via your tokenProvider. Never ship a static token in the binary, and don't commit real tokens to source control.

5. Initialize (once, at app start)

Configure the SDK before presenting any chat. The token is supplied through a provider so the SDK can refresh it on expiry (see Authentication).

Android

AiChatSdk.initialize(
    AiChatConfig(
        baseUrl = BuildConfig.AI_BASE_URL,          // injected, not hardcoded
        tenantId = "ctck-demo",                     // if the gateway model is used
        tokenProvider = { authRepository.freshAiToken() }, // suspend fun, may refresh
        theme = AiChatTheme(primary = Color(0xFF1565C0)),
        locale = AiChatLocale.VI,
    ),
)

iOS

AIChatSDK.initialize(.init(
    baseURL: AppConfig.aiBaseURL,
    tenantId: "ctck-demo",
    tokenProvider: { await authService.freshAIToken() },
    theme: .init(primary: .init(hex: 0x1565C0)),
    locale: .vi
))

Flutter

await AiChatSdk.initialize(AiChatConfig(
  baseUrl: const String.fromEnvironment('AI_BASE_URL'),
  tenantId: 'ctck-demo',
  tokenProvider: () => auth.freshAiToken(),
  theme: AiChatTheme(primary: Color(0xFF1565C0)),
  locale: AiChatLocale.vi,
));

React Native

import { AiChatSdk } from '@promvis/ai-chat-sdk';

await AiChatSdk.initialize({
  baseUrl: Config.AI_BASE_URL,
  tenantId: 'ctck-demo',
  tokenProvider: () => auth.freshAiToken(),
  theme: { primary: '#1565C0' },
  locale: 'vi',
});

6. Present the chatbot

Launch with a ticker and an optional mode — overview (quick take) or deep (in-depth). You may also seed an initial userMessage.

LaunchParams Type Required Notes
ticker String ✅ e.g. "HPG"
mode overview | deep — default overview
userMessage String? — seed the first question (e.g. a tapped suggestion)
onClosed callback — fired when the user dismisses the chat

Android — modal (Activity/Fragment host)

AiChatSdk.presentChatbot(
    context,
    LaunchParams(ticker = "HPG", mode = ChatMode.Overview),
    onClosed = { viewModel.refreshRateLimit() },
)

…or inline inside your Compose tree:

AiChatView(ticker = "HPG", mode = ChatMode.Overview, modifier = Modifier.fillMaxSize())

iOS

// SwiftUI
AIChatView(ticker: "HPG", mode: .overview)

// UIKit
let vc = AIChatViewController(ticker: "HPG", mode: .overview)
present(vc, animated: true)

Flutter

AiChatView(ticker: 'HPG', mode: ChatMode.overview) // embed in a sheet/page

React Native

import { AiChatView } from '@promvis/ai-chat-sdk';

<AiChatView ticker="HPG" mode="overview" style={{ flex: 1 }} />

7. Authentication & token refresh

  • The SDK authenticates every request with the header x-auth-token: <token> (not Authorization: Bearer).
  • tokenProvider is called on init and again whenever a request returns 401 mid-stream — the SDK swaps the header and resumes the SSE stream. Return a fresh, short-lived token; do not cache an expired one.
  • Your backend mints the token for the signed-in user (the trust model — S2S exchange vs OIDC federation — is open). The app never embeds a static, long-lived token.
// tokenProvider should be cheap when the cached token is still valid,
// and perform a real refresh when it isn't.
tokenProvider = {
    authRepository.cachedAiToken()?.takeIf { it.notExpired }
        ?: authRepository.refreshAiToken()
}

8. Theming (white-label)

Brand the chat to match your app via AiChatTheme at initialize():

Field Purpose
primary accent (buttons, user bubble, links)
secondary secondary accent
background / surface screen + card backgrounds
onSurface primary text color
fontFamily (optional) brand typeface
darkMode (optional) system | light | dark

For v1, token-level theming (colors + typography) is supported; deeper layout/density customization is on the roadmap.

9. Localization

Set locale to vi or en at init; all built-in strings and the assistant's response language follow it. Default is vi.

10. Guardrails & security

  • Advisory-only (hard rule). The chatbot is informational. It does not create orders, payments, OTP/SmartOTP, and it will not bridge into your trading APIs.
  • TLS per tenant. Transport uses standard system trust by default; optional certificate pinning can be supplied through config. The SDK ships no certificate-bypass logic.
  • No secrets in the app. baseUrl comes from your build config; the token comes from your tokenProvider. Nothing sensitive is baked into the binary.

11. Backend contract (for your BE team)

The SDK talks only to the Promvis Analyst AI endpoints below (header x-auth-token):

Endpoint Purpose
POST /api/chat/new open a chat thread → threadId
POST /agno-chat AG-UI RunAgentInput; SSE stream of TEXT_MESSAGE_*, CUSTOM, RUN_* events. Assistant replies may include ```assistant_chart blocks (chart schema v1.0).
GET /api/insights/ticker?ticker=<symbol> insight cards + suggested follow-up questions for the ticker

Your backend's job is to (a) mint the per-user token and (b) route to the correct tenant's Promvis Analyst instance.

12. Troubleshooting

Symptom Fix
OkHttp/dependency clash on Android the SDK relocates (shades) its OkHttp; if you still see a clash, align versions or report it
R8/Proguard strips rendering the SDK ships consumer rules; ensure you don't override them
iOS LaTeX renders blank known SwiftUI snapshot timing — fixed inside the SDK; update to the latest patch
401 loop your tokenProvider is returning a stale/expired token — return a freshly refreshed one
Chat shows offline fallback the SDK couldn't reach baseUrl or the token was rejected; check both

13. Versioning & support

  • The SDK follows SemVer; the public facade is stable within a major version.
  • A compatibility matrix maps each SDK x.y ↔ Promvis Analyst API vN (published with each release).
